# Suspense 原理与常见面试题

`Suspense` 解决的是：

`当组件依赖异步结果时，界面在“还没准备好”和“已经准备好”之间怎么平滑切换。`

它最核心的工作不是请求数据，而是管理两棵内容：

- 主内容 `content`
- 后备内容 `fallback`

## 关键认知

- 异步依赖未完成时，先展示 fallback
- 异步依赖完成后，再切回真正内容
- 它本质上是在协调异步组件 / 异步 setup 与渲染时机

## 常见面试题

## 1. Suspense 解决的核心问题是什么？

是异步依赖尚未就绪时，界面应该显示什么，以及何时切换到真实内容。

## 2. Suspense 和 loading 组件有什么区别？

loading 组件通常只是业务层条件判断；Suspense 是运行时层对异步依赖和渲染边界的统一协调。
