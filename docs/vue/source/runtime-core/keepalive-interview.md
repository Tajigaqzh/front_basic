# KeepAlive 原理与常见面试题

`KeepAlive`` 是 Vue 运行时里非常典型的“看起来像组件，实际在改渲染行为”的内置能力。

很多人会背一句：

“KeepAlive 可以缓存组件，避免反复销毁和重建。”

这句话没错，但太浅。真正面试时，更重要的是把它说成一个完整因果链：

`为什么要缓存 -> 缓存的是什么 -> 怎么缓存 -> 什么时候激活/失活 -> 和普通卸载有什么区别`

---

## 1. 为什么会需要 KeepAlive？

先看最常见场景：

- tab 切换
- 动态组件切换
- 路由页面来回切换

如果没有 `KeepAlive`，切换组件时会发生什么？

1. 旧组件被卸载
2. 组件实例销毁
3. DOM 被移除
4. effect 停止
5. 下次再切回来时重新创建实例、重新跑 setup、重新挂载

这会带来两个问题：

1. 性能浪费
   一些昂贵组件会不断重新创建
2. 状态丢失
   组件内部状态、滚动位置、表单输入等都可能重置

所以 `KeepAlive` 的目标不是“不切换”，而是：

`切换时不真正销毁实例，而是把它从当前显示树中摘出来，等下次再挂回去。`

---

## 2. KeepAlive 缓存的到底是什么？

很多人第一反应会说“缓存 DOM”，但这不准确。

`KeepAlive` 真正缓存的是一整套组件运行状态，至少包括：

- 组件实例
- 组件对应的 subTree
- 已创建的真实 DOM
- 组件 effect 和内部状态

所以它不是单纯把某段 HTML 留着不删，而是：

`把一个已经挂载完成的组件实例整包保留下来。`

这也是为什么被缓存的组件再次显示时，不需要重新跑完整初始化链路。

---

## 3. 它是怎么做到“不卸载，只隐藏”的？

核心思路是：

- 普通组件切走时，会走真正的 `unmount`
- 被 `KeepAlive` 包裹的组件切走时，不走真正销毁，而是走“失活”

可以把它理解成两种完全不同的离场方式：

### 普通卸载

- 从 DOM 树移除
- 销毁组件实例
- 清理 effect
- 生命周期结束

### KeepAlive 失活

- 从当前显示位置移走
- 挪到缓存容器
- 实例仍然存在
- effect / state / subTree 仍然保留
- 后续可以再激活回来

所以 `KeepAlive` 的本质，是把“卸载”改写成了“转移 + 缓存”。

---

## 4. 它在源码层依赖哪些关键能力？

`KeepAlive` 自己并不是一个普通业务组件，它会和 renderer 深度协作。

它主要依赖几类能力：

### 4.1 渲染器暴露的移动能力

因为缓存不是“记个 Map 就完事”，它真的要把 DOM 从当前容器移走。

所以它需要 renderer 提供：

- move
- unmount
- createElement

也就是说，`KeepAlive` 是运行时内部和渲染器耦合比较深的组件之一。

### 4.2 组件实例标记

被缓存的组件需要被区分成：

- 初次挂载
- 已缓存但当前失活
- 从缓存中重新激活

所以运行时会在 vnode / instance 上打标记，告诉 patch 流程：

`这个组件不是普通新建，也不是普通卸载，而是 KeepAlive 特殊路径。`

### 4.3 缓存索引结构

`KeepAlive` 一般会维护：

- 一个缓存表 `cache`
- 一个 key 顺序集合 `keys`

作用分别是：

- `cache`
  通过 key 快速找到缓存的 vnode / 实例
- `keys`
  维护缓存顺序，用于配合 `max` 做淘汰

---

## 5. `include / exclude / max` 是怎么影响缓存的？

这几个属性是面试高频点。

### `include`

表示只有命中的组件才允许进入缓存。

### `exclude`

表示命中的组件不要缓存。

### `max`

表示最大缓存数。

如果超过 `max`，Vue 会把最早缓存的一项淘汰掉。

注意这里的重点不是“能淘汰”，而是：

`被淘汰的组件会真的走卸载，而不是继续保留。`

所以 `KeepAlive` 不是无限缓存，它本质上是一种带策略的实例复用机制。

---

## 6. 激活和失活时会发生什么？

这是理解 `KeepAlive` 的关键。

### 失活

组件暂时不显示，但不销毁。

此时一般会发生：

- DOM 从当前容器移走
- 组件被标记为 deactivated
- 触发 `onDeactivated`

### 激活

组件重新显示。

此时一般会发生：

- 从缓存容器把 DOM 挪回显示位置
- 组件重新参与当前渲染树
- 触发 `onActivated`

所以：

- `mounted / unmounted` 对应真正生死
- `activated / deactivated` 对应缓存组件的显隐切换

这是面试里最容易被追问的一组生命周期区别。

---

## 7. KeepAlive 和普通组件更新的关系

很多人会误以为“被 KeepAlive 缓存后就不更新了”，这不对。

更准确地说：

- 它不会因为切走就被销毁
- 但只要组件重新参与当前树，它依然会按正常组件规则更新

也就是说，`KeepAlive` 解决的是“实例是否保留”，不是“组件永远不再更新”。

---

## 8. 常见面试题

## 1. `KeepAlive` 缓存的到底是什么？

不是只缓存 DOM，而是缓存组件实例、subTree、真实 DOM 和相关运行状态。

## 2. `KeepAlive` 为什么不等于 `display: none`？

因为 `display: none` 只是视觉隐藏，组件仍留在当前树里；而 `KeepAlive` 是把组件从当前显示链路摘出来，并改写它的卸载/激活行为。

## 3. `KeepAlive` 和普通卸载最本质的区别是什么？

普通卸载会销毁实例，`KeepAlive` 失活不会销毁实例，只是移出当前容器并保留缓存。

## 4. `activated` / `deactivated` 和 `mounted` / `unmounted` 的区别是什么？

- `mounted / unmounted`：真实创建和真实销毁
- `activated / deactivated`：缓存组件的恢复显示与临时离场

## 5. `max` 是怎么工作的？

缓存超过上限时，Vue 会淘汰最早进入缓存的那一项，被淘汰项会真正走卸载。

## 6. `KeepAlive` 为什么要和 renderer 深度协作？

因为它不只是记录状态，还要真实移动 DOM、跳过普通卸载、恢复缓存节点，这些都需要 renderer 提供底层能力。
