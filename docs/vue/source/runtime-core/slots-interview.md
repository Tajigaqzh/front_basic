# 插槽原理与常见面试题

插槽是 Vue 里一个很容易“会用，但解释不清”的点。

很多人只会说：

“父组件给子组件传一段模板，子组件在 `<slot />` 处渲染出来。”

这只是表层现象。真正从运行时角度看，插槽的关键是：

`插槽不是提前渲染好的 DOM 片段，而是父组件传给子组件的一组函数。`

这一点是理解插槽原理的核心。

---

## 1. 为什么插槽不能简单理解成“模板替换”？

如果只是字符串或模板片段替换，会有很多问题：

- 插槽内容里可能依赖父组件状态
- 插槽内容什么时候执行，会影响依赖收集
- 作用域插槽还要把子组件数据反向暴露给父组件

所以 Vue 最终选择的抽象不是“片段”，而是“可执行函数”。

这样就可以做到：

- 需要渲染时再执行
- 保留父组件作用域
- 可以向函数传参数，支持作用域插槽

---

## 2. 插槽的本质是什么？

从运行时看，插槽最终会变成类似：

```ts
slots = {
  default: () => [/* 一组 VNode */],
  header: () => [/* 一组 VNode */]
}
```

如果是作用域插槽，还会更像：

```ts
slots = {
  default: (slotProps) => [/* 用 slotProps 生成 VNode */]
}
```

所以：

`插槽本质上是“父组件传给子组件的一组返回 VNode 的函数”。`

---

## 3. 为什么插槽函数要在子组件内部调用？

这是非常高频的面试题。

先看现象：

- 插槽内容属于父组件
- 但调用时机在子组件内部

为什么这样设计？

因为子组件需要决定：

- 哪个位置渲染插槽
- 哪个命名插槽被使用
- 是否有 fallback 内容
- 调用插槽时要不要传 slot props

所以运行时模型是：

1. 父组件生成插槽函数
2. 子组件接收这些函数
3. 子组件在自己的 render 里调用对应插槽函数

这样既保留了父作用域，又让子组件掌握布局权。

---

## 4. 普通插槽和作用域插槽的区别是什么？

### 普通插槽

父组件只传内容，不需要子组件反向给数据。

### 作用域插槽

子组件调用插槽函数时，会传入一份参数：

```ts
slots.default({ item, index })
```

父组件在插槽函数里接住这些参数，再决定渲染什么。

所以：

- 普通插槽：父传内容
- 作用域插槽：子传数据，父决定内容

更准确地说，作用域插槽其实是：

`子组件向父组件暴露渲染时机和一组渲染参数。`

---

## 5. 运行时里插槽主要在哪些文件处理？

### `componentSlots.ts`

负责：

- 初始化 slots
- 规范化 slots
- 更新 slots

### `helpers/renderSlot.ts`

负责：

- 在 render 期间真正渲染某个 slot
- 处理 fallback 内容
- 处理编译优化信息

### `helpers/createSlots.ts`

负责：

- 把编译期生成的动态插槽结构整理成运行时可消费形式

所以插槽不是单点逻辑，而是一条链：

`父组件生成插槽函数 -> 子组件初始化 slots -> renderSlot 调用具体 slot`

---

## 6. 插槽为什么和普通 children 不一样？

普通 children 更像是：

- 已经确定好的子节点数据

而 slots 更像是：

- 延迟执行的“子节点生成器”

差别在于：

- 普通 children 是值
- slots 是函数

这个区别非常重要，因为它会直接影响：

- 依赖收集归属
- 渲染时机
- 动态更新能力

---

## 7. 插槽和作用域的关系

这里最容易混乱的一点是：

“插槽内容写在父组件模板里，为什么还能拿到子组件给的参数？”

答案是：

- 插槽函数本身是在父组件作用域里定义的
- 但函数调用发生在子组件里
- 子组件调用时把 slot props 作为参数传进去

所以作用域插槽并不是“子组件作用域泄漏到父组件”，而是：

`子组件调用父组件提供的函数，并在调用时传入参数。`

---

## 8. 常见面试题

## 1. 插槽的本质是什么？

本质是一组函数，而不是一段预渲染的 DOM。

## 2. 为什么插槽函数要在子组件内部执行？

因为子组件才知道布局位置、fallback 内容、调用时机，以及是否要向插槽传 slot props。

## 3. 作用域插槽的本质是什么？

本质是子组件调用父组件提供的插槽函数，并在调用时传入一组参数。

## 4. 为什么插槽和普通 children 要分开处理？

因为普通 children 是静态值或普通 VNode 集合，而插槽是延迟执行函数，语义和更新方式完全不同。

## 5. 插槽更新时，谁触发谁？

插槽内容本质上仍属于父组件 render 结果，所以很多场景下插槽内容更新的根源仍是父组件状态变化；但调用和布局控制发生在子组件内部。
