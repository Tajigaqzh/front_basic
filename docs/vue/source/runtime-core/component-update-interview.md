# 组件更新链路常见面试题

这份文档专门回答一个高频大题：

`一个组件的数据变化后，到 DOM 更新，中间到底经历了什么？`

## 标准回答链路

1. render 中读取响应式数据
2. 当前组件更新 effect 被收集为依赖
3. 数据变化时触发 effect
4. effect 不直接同步重跑，而是交给 scheduler
5. scheduler 去重、排序、放入微任务
6. flush 时重新执行组件 render
7. 生成新的 subTree
8. `patch(oldSubTree, newSubTree)`
9. 把最小变更落到宿主环境

## 常见面试题

## 1. 为什么组件更新不是同步立即执行？

因为同一轮同步代码里可能多次修改状态，调度器会把这些更新合并，避免重复 render。

## 2. 组件更新和 watcher 更新是什么关系？

它们都进入同一套 scheduler，只是优先级和 flush 时机可能不同。

## 3. `nextTick` 为什么能拿到更新后的 DOM？

因为它等待的是当前这轮调度刷新结束后的微任务时机。
